# H2Fleet AI/ML Architecture (docs/AI.md)

Owner: `services/python/ml-platform/**` (+ the model-loading upgrade in
`services/python/predictive-maintenance`). Everything runs inference **on
CPU**; every model is ≤ 200k parameters so CPU training takes seconds-to-minutes.

> ## Honest status — read this first
> All shipped artifacts (`ml-platform/artifacts/*/v1.0.0`) are trained on
> **SYNTHETIC bootstrap data** generated by `ml-platform/data/synth.py`.
> The platform does not yet have real failure labels (a handful of seeded
> incidents only), so *no metric below says anything about real-world
> accuracy*. These models have **never been validated on real failures**.
> The pipeline (synth → train → registry → serve → A/B → drift → continuous
> training) is real and production-shaped so that swapping the data source to
> `--source postgres` / `--source iceberg` is the only change needed as real
> telemetry accumulates.

## 1. Architecture

```
                 ┌──────────────────────── training ─────────────────────────┐
 synth parquet   │  training/train.py (synth|postgres|iceberg, --finetune,   │
 (data/synth.py) │  --ray, MLflow, best-val checkpointing, group/chrono       │
 Postgres ─────► │  splits) ──► artifacts/<model>/<version>/ ──► registry.json│
 lakehouse  ───► │  training/continuous.py: fine-tune→eval→promote-if-better │
                 └───────────────────────────────────────────────────────────┘
                                       │ MODEL_ARTIFACTS_DIR (shared volume)
              ┌────────────────────────┴─────────────────────────┐
              ▼                                                 ▼
 ml-platform :8095 (app/main.py)                  predictive-maintenance :8090
 5 scoring endpoints, /v1/ml/models,              prefers maintenance_lstm
 /v1/ml/drift, A/B champion/challenger,           artifact via app/lstm_model.py;
 JWT (h2fleet_auth), /metrics                     sklearn joblib → rules fallback
```

Supporting flows: `training/export_graph.py` pushes the route/station/depot
graph to Neo4j (optional) and to the GNN adjacency npz. The drift monitor
compares live request features against the quantile baselines shipped inside
each artifact.

## 2. Model cards

All metrics below: **version v1.0.0, measured on the SYNTHETIC test split**
(group-aware bus/route splits for maintenance/leak/carbon, chronological split
for demand, node holdout for the GCN). Source: `source: synth` in every
`metrics.json`.

### maintenance_lstm — component failure risk + time-to-failure
- **Arch:** LSTM(hidden 32, 1 layer) over (T=48, 5) windows → sigmoid risk head
  + softplus days head, per component. **5,256 params.**
- **Features:** h2_level_pct, fuel_cell_kw, battery_soc_pct, speed_kph,
  ambient_temp_c (z-normalised with train stats stored in the artifact).
- **Targets:** risk = failure within 14 days; days-to-failure (censored at 60).
- **Synthetic metrics:** mean AUC **0.750** (fuel_cell 0.891, compressor 0.669,
  tank_valve 0.488, battery 0.954), MAE days-to-failure 34.3 d.
- **Limitations:** tank_valve is barely above chance even on synthetic data —
  its stiction signature is weak at 5-min cadence; expect this to be the
  hardest component on real data too. Trained on simulated degradation ramps,
  not real wear.

### demand_forecaster — next-24h ridership per route
- **Arch:** GRU(hidden 64) over 72h history → 24 outputs. **19,928 params.**
- **Features:** ridership + hour/dow cyclical encodings, weekend flag, temp,
  precip. Ridership channel and target are scaled **per window** by the
  window's own mean (shape learning; route-scale invariant; replicated in
  serving via the `per_window_scaling` schema flag).
- **Synthetic metrics:** MAE **6.4 riders/h**, RMSE 9.3, rel-MAE **0.126**
  (persistence baseline rel-MAE 0.447 on the same split).
- **Limitations:** weather is synthetic sinusoids; no special events; real
  ridership must come from fare/AFC data (postgres loader currently uses
  settled fares per hour at an `ALL` grain — routes are not recorded yet).

### leak_autoencoder — H2 leak anomaly score
- **Arch:** dense AE 8→16→8→4→8→16→8, trained on normal vectors only.
  **636 params.** Score = per-row reconstruction MSE; threshold = p99 of val
  normal error (2.14, stored in the artifact).
- **Features:** h2 ppm × 4 zones, tank pressure, pressure drop, flow rate,
  ambient temp.
- **Synthetic metrics:** AUC **1.0**, TPR 1.0 at FPR 0.97%.
- **Limitations:** synthetic leaks are deliberately strong (γ-distributed ppm
  spikes in clusters); AUC 1.0 will NOT hold on real sensor noise. Threshold
  must be recalibrated with real incident data before alarming.

### fleet_gcn — delay/energy propagation over the fleet graph
- **Arch:** 2-layer GCN, **pure PyTorch** — adjacency normalised manually as
  D^-1/2(A+I)D^-1/2, layer = Â·X·W (no torch_geometric). **434 params.**
- **Graph:** 17 nodes (3 stations + 2 depots + 12 route termini), undirected
  edges; exported from Postgres by `training/export_graph.py`.
- **Synthetic metrics:** delay propagation MAE **0.22 min**, H2 impact MAE
  0.086 kg (node holdout).
- **Limitations:** targets come from a synthetic 2-hop diffusion model; the
  graph topology is a proxy until a routes table exists; delay/queue node
  features are placeholders until the twin/dispatch services publish them.

### carbon_forecaster — CO₂ avoided per period
- **Arch:** dense MLP (8→64→64→1) on period aggregates, predicting the
  z-normalised target. **4,801 params.**
- **Synthetic metrics:** MAE **50.3 kg**, rel-MAE **0.018** (at the 2% label
  noise floor of the generator).
- **Limitations:** the diesel baseline (1.15 kgCO₂/km) and green-H₂ assumption
  are constants; real accounting must reconcile with
  `citizen.carbon_credits`.

## 3. Guides

### Train / fine-tune
```bash
cd services/python/ml-platform
python -m training.train --model all --source synth --epochs 8 --register
python -m training.train --model maintenance_lstm --source postgres \
    --finetune-from artifacts/maintenance_lstm/v1.0.0
python -m training.train --model all --source iceberg --lakehouse-dir /mnt/lake
```
Splits are leakage-free (see model cards). Best-on-validation weights are
checkpointed and saved with `metrics.json` + `feature_schema.json`
(features, normalisation stats, drift baselines). `--ray` runs the train
function through ray when installed, with automatic local fallback.

### Continuous training
`training/continuous.py` (cron/Temporal; suggested: nightly 02:30
`--once --source postgres`, weekly full retrain): pulls the newest data,
fine-tunes from the champion, evaluates on held-out data, and promotes only
if the primary metric improves (updates `registry.json`, transitions the
MLflow stage/alias when configured). Non-improving candidates become the
`challenger` and immediately receive `AB_SPLIT` traffic for observation.

### MLflow registry
Set `MLFLOW_TRACKING_URI` (+ `pip install mlflow`). train.py logs
params/metrics/artifact bundles per run; continuous.py transitions
`h2fleet-<model>` to the champion alias/`Production` stage on promotion. When
unset or mlflow missing, everything is a graceful no-op and `registry.json`
remains the source of truth.

### A/B + drift ops
- Champion/challenger via `artifacts/registry.json`; deterministic hashed
  assignment (`AB_SPLIT`, default 0.1); responses and logs are variant-tagged.
- Drift: PSI + binned KS vs the artifact's training baselines; background
  loop (`DRIFT_INTERVAL_S`), `GET /v1/ml/drift`, warning logs at PSI > 0.2,
  Prometheus gauge `ml_feature_drift_psi{model,feature}`. Drift is a
  detection aid — promotion stays with continuous.py, not auto-retraining.

## 4. CPU performance notes

- Params: 434–19,928 per model; full synthetic training of all five models:
  ~70 s total on 2 vCPU (maintenance LSTM dominates, ~36 s).
- Inference: single scoring call < 10 ms per model on CPU (batch=1, torch
  no_grad, eval mode); the server scores in `asyncio.to_thread` so the event
  loop is never blocked.
- Docker image pins the CPU-only torch wheel
  (`--index-url https://download.pytorch.org/whl/cpu`) — no CUDA in the image.

  `ml-platform` and `predictive-maintenance` (continuous training writes,
  both services read).
- optional `mlflow` server (profile `ml`): env `MLFLOW_TRACKING_URI=http://mlflow:5000`.
- optional `neo4j` (profile `graph`): env `NEO4J_URI=bolt://neo4j:7687`,
  `NEO4J_USER`/`NEO4J_PASSWORD` for `training/export_graph.py`.
- optional `ray` head (profile `ray`) for `--ray` training; local fallback
  means it is never required.
- cron/Temporal schedule for `training/continuous.py --once`.

## Reproducing trained artifacts
Trained weights (`artifacts/**/weights.pt`) are binary and not committed to git. Regenerate
deterministically (seeded) with: `cd services/python/ml-platform && python -m training.train --model all`
(add `--source postgres` once live telemetry has accumulated, `--finetune-from` for continuous training).
