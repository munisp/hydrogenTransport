# Wave-6 Auditor A4 — Safety / Security / Regulatory

Evidence = actual code reads (file:line). Excludes SECURITY_AUDIT.md,
INSIDER_THREAT.md, INCIDENT_RESPONSE.md content already delivered.

## Gaps

### A4-01 — No driver SOS / panic button: a driver under threat has no platform channel
- **Scenario:** A driver is assaulted at a stop, or discovers a hijack
  attempt. The platform knows the bus, the driver (dispatch job), the
  position (telemetry) — but there is no SOS endpoint, no critical incident
  type, no alert. The only safety ingress is the H2 sensor webhook.
- **Why unhandled:** grep `sos|panic|distress` across services + mobile =
  zero (only Go `panic` in code comments).
- **Recommended fix:** `POST /v1/safety/sos` (driver JWT): opens a
  `critical` incident of type `sos` with bus/driver/last-position context
  attached, publishes `safety.sos`, triggers webhook delivery (A3-03).
- **Size:** M · **Class:** FIX-NOW

### A4-02 — Incident type is a free-text string: crash / PRD vent / evacuation are indistinguishable from typos
- **Scenario:** An operator reports a collision by POSTing
  `{"type":"acident"}` (typo). It is stored verbatim; no escalation rule,
  no severity floor, no workflow matches it; the Temporal incident
  workflow only ever starts for leak signals.
- **Why unhandled:** `incidents.go:87-117` requires only `Type != ""`;
  severity defaults to `medium` regardless of type
  (`incidents.go:91-93`); `IncidentResponseWorkflow` is leak-signal-only
  (`workflows.go:66-76`).
- **Recommended fix:** validate `type` against an enum
  (`h2_leak|collision|fire|prd_vent|evacuation|sos|security|breakdown|
  other`) with a per-type minimum severity floor (collision/prd_vent/
  evacuation ≥ high, sos/fire = critical); reject unknown types 422.
- **Size:** S · **Class:** FIX-NOW

### A4-03 — No read-only regulator/auditor role: oversight requires handing out platform-admin
- **Scenario:** The national hydrogen-safety regulator and the city's
  internal audit both need read access to the audit chain and incident
  history. Today the only role that can `GET /v1/audit` is
  `platform-admin` — which can also rotate toggles, approve onboarding and
  refund payments. Oversight access violates least privilege by
  construction.
- **Why unhandled:** `audit-log/cmd/server/main.go:70-74` gates reads with
  `RequireRole("platform-admin")`; the role set across services is
  operator / platform-admin / driver / station-staff (grep of all
  RequireAnyRole/RequireRole call sites).
- **Recommended fix:** add `auditor` role: read access to `/v1/audit*`,
  `/v1/audit/verify`, incident list/detail, compliance endpoints; zero
  write access anywhere. Document in Keycloak realm setup.
- **Size:** S · **Class:** FIX-NOW

### A4-04 — No chain-of-custody evidence export for an incident
- **Scenario:** After a station fire, the insurer and the prosecutor demand
  a tamper-evident bundle: the incident timeline, the raw sensor readings,
  the telemetry window, and proof nothing was altered. Operators must
  hand-assemble SQL dumps; the hash-chain verification exists
  (`/v1/audit/verify`) but there is no per-incident export.
- **Why unhandled:** no export endpoint correlating incident ↔ audit events
  ↔ telemetry window ↔ verification proof.
- **Recommended fix:** `GET /v1/incidents/{id}/evidence-pack` (auditor/
  platform-admin): JSON bundle of incident row, status transitions,
  matching audit-log slice, ±15 min telemetry for the bus/station, and the
  chain-verification result for the included audit slice.
- **Size:** M · **Class:** FIX-NOW

### A4-05 — No hours-of-service / fatigue guard: a driver can be dispatched for a 16-hour shift
- **Scenario:** During a driver shortage, dispatch creates back-to-back
  jobs: 05:00–13:00 and 13:00–21:00 for the same driver — 16 h behind the
  wheel, illegal under EU 561/2006-style regimes and lethally unsafe with
  high-pressure H2 aboard.
- **Why unhandled:** `CreateDispatchJob` validates only `ends_at >
  starts_at` (`dispatch.go:114-118`) and overlap; nothing bounds duration
  or daily totals.
- **Recommended fix:** configurable limits: `DISPATCH_MAX_SHIFT_HOURS`
  (default 10) per job and `DISPATCH_MAX_DAILY_HOURS` (default 10) summed
  over active jobs per driver per day; 422 with a descriptive error on
  breach (override = platform-admin, audited).
- **Size:** M · **Class:** FIX-NOW

### A4-06 — H2 station emergency (station-side, not bus-side) has no distinct workflow
- **Scenario:** A station's PRD vents 350-bar hydrogen, or a dispenser hose
  separates during fueling. The leak webhook accepts `station_id`, and
  severity-from-ppm escalation works — but nothing station-specific
  follows: the queue keeps admitting buses to a venting station, chargers/
  dispensers are not auto-closed, no muster/evacuation state exists.
- **Why unhandled:** `IngestLeak` opens/updates an incident and publishes
  events; `JoinStationQueue` (`queue.go:86+`) never consults open critical
  incidents for the station; there is no station emergency state.
- **Recommended fix:** on a `critical` incident with `station_id`:
  automatically set the station status to `emergency` (existing station
  status enum), reject new queue joins with 409 while a critical incident
  is open, publish `station.status.changed`. Reopen requires incident
  resolution.
- **Size:** M · **Class:** FIX-NOW

### A4-07 — Credential revocation is assumed-instant; there is no revocation drill or propagation SLA
- **Scenario:** A driver's phone with a valid refresh token is stolen at
  22:00. Keycloak can revoke the session — but nothing documents who does
  it, how fast tokens die (access-token TTL = the effective revocation
  latency), or proves the revoked subject is actually rejected.
- **Why unhandled:** docs/INCIDENT_RESPONSE.md covers platform incidents;
  no credential-compromise runbook; token TTLs not asserted anywhere.
- **Recommended fix:** docs/INCIDENT_RESPONSE.md section: revocation
  runbook (Keycloak admin steps, expected propagation = access-token TTL,
  verification step calling an authed endpoint with the revoked token) +
  assert short access-token TTL in realm config notes. Doc this wave.
- **Size:** S · **Class:** FIX-NOW (doc)

### A4-08 — No DPIA / data-protection artifact set despite driver+passenger surveillance-grade data
- **Scenario:** The DPO asks for the DPIA covering continuous GNSS tracking
  of drivers, passenger payment linkage, and station CCTV-adjacent sensor
  data. The hardware guide (§6) says "run a DPIA" — the platform docs
  don't have one.
- **Why unhandled:** docs/ has security/insider/IR docs, no data-protection
  impact assessment, no record of processing (Art. 30).
- **Recommended fix:** docs/DPIA.md — processing inventory (data domains,
  purposes, legal basis, retention cross-ref to A3-05, risks, mitigations
  already in-platform: pseudonymous subs, retention, erasure hook, RBAC).
- **Size:** S · **Class:** FIX-NOW (doc)
