# Wave-6 Auditor A2 — Business-Domain Use Cases

Evidence = actual code reads (file:line). Excludes Wave-4 business-rule
fixes (docs/BUSINESS_LOGIC_AUDIT.md) and Wave-5 energy vectors.

## Gaps

### A2-01 — No fare products at all: every ride is a single full-fare tap
- **Scenario:** The city sells a €49 monthly pass, a student concession
  (50 % off), and a senior free-travel entitlement. None of these riders can
  be represented: every `POST /v1/payments` charges `amount_minor` (capped
  by the daily cap only). A pass holder is charged full fare for every ride;
  there is no product catalog, no entitlement, no concession.
- **Why unhandled:** grep for `subscription|concession|season_pass|monthly`
  across commerce-api/citizen-api returns nothing;
  `handlers/payments.go:88-150` resolves price = requested amount ± cap.
- **Recommended fix:** migration 0009: `commerce.fare_products`
  (pass|discount|free, validity, price) + `commerce.rider_entitlements`
  (rider_sub, product, valid_from/to); `CreatePayment` resolves the best
  active entitlement first (free pass → charge 0; discount → reduced
  amount), then applies the daily cap. Entitlement CRUD for operators.
- **Size:** L · **Class:** FIX-NOW

### A2-02 — Full refunds only: no partial refund
- **Scenario:** A rider is charged €4.00 for a journey the bus abandoned
  halfway; policy refunds €2.00. The operator must either refund everything
  or nothing.
- **Why unhandled:** `RefundPayment` (`payments.go:399-470`) always reverses
  `effectiveCharged()` in full; the request takes no amount.
- **Recommended fix:** optional `amount_minor` in the refund body (≤ charged,
  > 0); partial refund posts a partial reversal, marks the payment
  `partially_refunded` and keeps it refundable for the remainder
  (deterministic transfer id per refund ordinal).
- **Size:** M · **Class:** FIX-NOW

### A2-03 — Currency is a free-text field that the ledger silently ignores
- **Scenario:** A client bug (or an attacker) posts `{"amount_minor": 500,
  "currency": "USD"}`. The payment is stored as "USD" but the TigerBeetle
  transfer moves 500 minor units of the platform's single-currency (EUR)
  ledger. Financial records now disagree with ledger reality.
- **Why unhandled:** `payments.go:110-112` defaults empty → "EUR" but
  accepts any other string unchecked; `ledger.Transfer` has no currency
  dimension.
- **Recommended fix:** reject any currency ≠ configured platform currency
  (`PLATFORM_CURRENCY`, default EUR) with 422 — fail loud, not silent
  mis-posting.
- **Size:** S · **Class:** FIX-NOW

### A2-04 — DRT has no accessibility model: wheelchair users cannot book
- **Scenario:** A wheelchair user requests a demand-responsive ride. There
  is no way to state the requirement, no vehicle attribute to match against,
  and no capacity check — the nearest-bus picker may send a non-accessible
  vehicle that cannot board the rider.
- **Why unhandled:** `createDRTRequest` (`drt.go:55-61`) has passengers but
  no accessibility fields; `fleet.vehicles` (0001_core.sql:36-41) has no
  seats/wheelchair attributes; `PickVehicle` filters only status+distance.
- **Recommended fix:** migration 0009: `fleet.vehicles.wheelchair_accessible
  bool`, `citizen.drt_requests.requires_wheelchair bool`; `PickVehicle` and
  `AssignDRT` filter/validate on it.
- **Size:** M · **Class:** FIX-NOW

### A2-05 — Chargebacks / payment disputes have no representation
- **Scenario:** A rider disputes a card charge with their bank; the funds
  are pulled back outside the platform. Operations must reconcile: which
  payment, how much, wallet correction, loyalty correction.
- **Why unhandled:** grep `dispute|chargeback` = no handler, no schema, no
  status. Only operator-initiated refunds exist.
- **Recommended fix:** document the contract — Mojaloop (the settlement
  rail) has no chargeback primitive by design; card-rail chargebacks arrive
  via the acquirer and are processed as an operator refund + reconciliation
  note. Add `disputed` status documentation to the payments API contract;
  no code this wave beyond the doc + refund path (A2-02 covers the
  mechanics). CONTRACT.
- **Size:** S · **Class:** CONTRACT

### A2-06 — No corporate/employer accounts or group settlement
- **Scenario:** An employer buys mobility for 200 staff and wants one
  monthly invoice; a school books daily transport for a class. Today every
  payment is rider→operator with per-ride settlement.
- **Why unhandled:** single-payer model baked into `CreatePayment`
  (payer == JWT subject, `payments.go:118-126`); no billing-account entity.
- **Recommended fix:** product decision — implementable later on top of
  fare products (a `payer_account` on entitlements). Documented as DECISION
  with the extension path named; not built this wave.
- **Size:** L · **Class:** DECISION

### A2-07 — Driver payroll / hours-of-service data is not derivable
- **Scenario:** Payroll needs each driver's hours per week. Dispatch jobs
  have starts_at/ends_at but there is no check-in/check-out, no break
  model, and nothing prevents a 16 h job (see A4-05 for the safety angle).
- **Why unhandled:** `infra.dispatch_jobs` is a schedule, not a time clock;
  no attendance events anywhere.
- **Recommended fix:** out of scope for a fleet platform's transactional
  core — document the integration contract (payroll consumes
  `infra.dispatch_jobs` + audit events via the open-data/audit exports).
  The *safety* half (fatigue limits) is fixed in A4-05.
- **Size:** — · **Class:** CONTRACT

### A2-08 — Ad inventory sells placements but there is no advertiser self-service or invoicing
- **Scenario:** A local business wants to buy bus-side ad slots directly,
  upload creative, and get invoiced. Today only operators create inventory
  and placements; billing is a cost field, not an invoice.
- **Why unhandled:** `handlers/advertising.go` is operator-only CRUD +
  placement costs (0007); no advertiser role, no approval workflow, no
  invoice artifact.
- **Recommended fix:** DECISION — self-service ad sales is a separate
  product surface; document the extension path (advertiser role +
  placement approval states + invoice export).
- **Size:** L · **Class:** DECISION

### A2-09 — School transport / charter bookings have no vehicle-block reservation
- **Scenario:** A school charters 3 buses for a field trip 09:00–15:00.
  Nothing stops dispatch from assigning those buses to routes in that
  window unless someone hand-creates fake dispatch jobs.
- **Why unhandled:** the only reservation primitive is the dispatch job
  itself (`dispatch.go`); no booking/charter entity.
- **Recommended fix:** partially solved by A1-05's swap + the existing
  overlap engine: a charter IS a dispatch job with `route='charter:<ref>'`.
  Document the convention; full charter product = DECISION.
- **Size:** S · **Class:** DECISION (convention documented)
